# 口述史事件时间线核对

供口述史整理者核对多个事件“先后描述”是否自洽的小工具。整理者把访谈中得到的两事件时间差区间逐行粘贴，后端把全部区间联立为**差分约束系统**：

- 若约束互相矛盾，返回一条由**原始行号与对应上下界**构成的**闭合矛盾链**（负环），说明是哪几句话“打了架”；
- **冲突单行修订建议**：文本语法有效但联立矛盾时，逐行暂时移除该行的上、下界约束——其余行仍矛盾的行排除；其余可解时求这两个事件时间差的**最紧可行区间**，只放宽该行**一个端点**至首次相交的整数分钟，给出**最小改动量、替换后的整行**与迫使该端点移动的**原始行号、界值推导链**；建议按改动分钟数、原始行号排序，无单行修复时明确提示；
- 若无矛盾，返回一条以**最早事件为第 0 分钟**、满足全部区间的可行时间线，并逐条核对每个区间；
- **绝对时间锚定**：在区间文本旁粘贴多行 `事件名,YYYY-MM-DD HH:MM` 锚点（同一无时区本地时间），后端把每个锚点作为**事件相对统一零点的等式**与区间一起联立——同名锚点重复也参与判定；锚点与区间或彼此冲突时返回含**区间行号、锚点行号与所用界值**的闭合矛盾链；可解时只为**与锚点连通**的事件显示绝对日期时刻（精确点或范围），其余标为**“未定位”**，不把任何任意平移量当作真实日期；
- **约束冗余核对**：任选一条原始行，删去该行对应的上、下界约束后，求其余约束对这两个事件时间差的**最紧下界与上界**——推不出的端点标为**无界**，有界端点给出**推导路径、原始行号与所用界值**；仅当推导区间完全落在所选行区间内时判为**“可删”**，否则标为**“必要”**；
- **两版比较**：分别粘贴**基准文本**与**修订文本**，后端对两版**各自独立校验、独立联立**后，以**基准中首次出现的共同事件**为两版**共享参考事件**，对每个共同事件分别求它相对参考事件的**最紧时间差上下界**（复用冗余核对同款最短路推导）：**任一端点（下界或上界）在两版间不同才计为变化**，**不比较两版各自“最早事件归零”的样本时刻**（新增事件会改变另一版的归零原点，样本时刻差只是整体平移假象）；表格给出**两版区间与端点差值**，变化端点附**两版各自的原始行号、所用界值与连续推导路径**（修订版路径上的行另标注相对基准“已修改/新增/区间未改”）。事件**仅在两版中均与参考连通时可比**，否则标为**“不可比”**，隐藏端点差值与变化证据；**没有共同事件时只列新增、删除**；任一版无效或互相矛盾时，分别返回该版错误或闭合矛盾链，**不生成任何差异结论**；
- **互斥说法下的先后查询**：区间文本作**共同约束**，另输入最多 6 行**候选组**（每行 `区间A | 区间B`，两条说法只能选一条，两侧沿用区间格式），后端**枚举全部组合**与共同约束联立、**排除冲突组合**；对每个可行组合求 `t(乙) − t(甲)` 的**最紧上下界**，再跨组合取**最小下界、最大上界**（任一组合对应端无界则合并端无界）：合并下界 ≥ 1 分钟判**“甲始终先于乙”**，合并上界 ≤ −1 分钟判**“甲始终后于乙”**，否则判**“不确定”**；无可行组合时不作先后判断；
- **最少撤回**：当若干句叙述无法同时成立时，对最多 **10 条非空有效约束**按**撤回行数递增**搜索，返回所有使剩余约束可行的**最少撤回原始行号组合**；每个方案展示剩余约束的**一条可行时间线**（撤回全部行时显示空时间线）；**空约束集视为可行**，原文已可行时返回**零撤回方案**；语法错误或超限给出明确提示；
- **事件别名归并核对**：同一事件被记成多个名字时，在区间文本旁逐行填写 `事件名,同一事件的另一名称`，后端用**并查集按传递关系**把名称归为同一事件（A=B、B=C ⇒ A、B、C 同组），每组取区间文本中最先出现的名称作**统一事件名**，再用归并后的节点联立原区间——**同组内的区间也参与判定**（归并后要求 0 落在该行区间内）；归并造成矛盾时返回保留**原始区间行号与别名组**（每组原名称）的冲突说明，可解时展示**按统一事件归并的时间线及每组原名称**。
- **行程可达性核对**：逐行填写**事件地点** `事件,地点`、有向**通行路段** `起点,终点,分钟`（非负分钟，重复路段取最短）与**按发生顺序排列的事件名**（每行一个），继续沿用页面上的时间差区间。对每对相邻事件求地点网络中的**最短通行时间**（**同地点按零分钟**，Dijkstra），把“后一事件 − 前一事件 ≥ 最短通行”与原区间联立：**无路可达**时指出对应事件段；**时间冲突**时给出含**原区间行号、事件段及其最短路线**的闭合矛盾依据；**可行**时列出各段**最短路线、所需分钟**与一条满足全部约束的**时间线**（含事件地点、实际间隔与富余）。另校验重复事件地点、缺失事件地点、重复行程事件与负通行时间。
- **有序事件最大统一间隔**：沿用首页事件区间，另按希望保持的先后顺序逐行填写**至少两个互不相同、已在区间中出现**的事件名，后端求最大的非负整数 **g**，使**每对相邻所选事件至少相隔 g 分钟**且全部原区间同时成立，返回 g 与一条**达到该间隔的完整可行时间线**；原区间可行但所选顺序**连 g=0 都无法保持**时明确提示**顺序冲突**（含顺序间隔环节的闭合矛盾链）；g **没有有限上限**时显示**“无上限”**并给出 g=0 的可行时间线；原区间语法错误或自身矛盾时沿用现有错误或闭合矛盾链。
- **记录时钟对齐**：沿用首页事件区间，另逐行输入 `来源,事件,本地分钟`。**首个出现的来源为参考时钟**（偏移固定为 0）；同一来源的全部记录共用一个整数分钟偏移，**事件真实分钟 = 本地分钟 + 偏移**。后端把每条记录写成一对等式边，与区间复用同一套差分约束 Bellman-Ford 联立；矛盾时返回含**区间行号或记录行号、所用界值**（本地分钟）的**闭合冲突链**；可解时给出各来源相对参考时钟的**最紧偏移上下界**（精确点或范围），**未与参考来源连通**的来源标为**“未定位”**，不显示伪精确偏移。
- **全局容差评估**：沿用首页事件区间，每条有效区间 `[lo,hi]` 同时向两侧扩为 `[lo−k,hi+k]`（**k 为非负整数分钟**），后端用同一套差分约束 Bellman-Ford 求**使全部约束可解的最小 k**（先试 k=0，不可行时先指数放大 1、2、4、… 找到可行上界再二分）。返回最小 k、一条**扩展后可行时间线**（最早事件为第 0 分钟）与**每行原区间、扩展区间的实际差值**（下界/上界各放宽 k、本时间线差值、距扩展两端富余、原区间是否本来就满足）；**k>0** 时另给出 **k−1 时含原始行号与所用扩展界值的闭合冲突链**：环上原界权之和 W<0、环长 L，每条边统一放宽 k 分钟使环权变为 W+Lk，需 `k ≥ ⌈−W/L⌉`（恰好等于最小 k），说明为何不能再缩小一分钟。原区间已可解时最小 k=0；空约束集视为可行（k=0、空时间线）；语法错误沿用逐行报错。**分钟全程精确**：求解用任意精度整数，接口的所有分钟字段（k、时间线分钟、区间端点、放宽量、实际差值、富余、冲突链界值与环权、所需容差）一律以**十进制字符串**传输（计数与行号保持数值），前端按 **BigInt** 整数运算与展示——`9007199254740993` 这类超出 JS 安全整数范围的分钟也不会被截断或转浮点。

技术栈：Python 3.11 + FastAPI + 原生 JavaScript（无前端构建、无 npm）。

## 输入格式

每行一条：

```
事件甲,事件乙,最少分钟,最多分钟
```

含义：`最少分钟 ≤ 事件乙时刻 − 事件甲时刻 ≤ 最多分钟`（即“乙比甲晚”的时间差区间，分钟为整数；允许负数表示乙实际更早）。

- 支持半角 `,` 与中文逗号 `，`；
- 空行会被跳过，但**行号按原始文本计算**，矛盾链与错误提示引用的都是原始行号；
- 每行校验：事件名非空、上下界为整数、下界不大于上界。

示例（无冲突）：

```
起床,洗漱,10,30
洗漱,早饭,15,45
早饭,出门,20,60
出门,开会,40,90
起床,开会,80,240
```

页面上可一键填充“可行示例”与“矛盾示例”。

## 事件别名归并核对

同一事件在口述中常被记成多个名字（如“洗漱”又写作“盥洗”）。整理者在“事件区间”旁的**“事件别名”**框中逐行填写：

```
事件名,同一事件的另一名称
```

含义：该行的两个名称指同一事件。后端用**并查集按传递关系归并**（A=B、B=C ⇒ A、B、C 同组），每组取**区间文本中最先出现**的名称作**统一事件名**（未在区间出现的组取别名文本中最先出现的名称），把区间行两端替换为统一事件名后复用同一套差分约束 Bellman-Ford 联立：

- **同组内的区间也参与判定**：两端归并为同一事件的区间行成为自环约束，等价于要求 **0 落在该行区间内**（下界为正或上界为负即构成冲突）；
- **冲突**：归并造成矛盾时，返回保留**原始区间行号**的闭合矛盾链（每一步另附该行的**原始事件名**），并列出参与归并的**别名组**（每组统一事件名与原名称）；
- **可解**：展示**按统一事件归并的时间线**（每个节点附该组原名称）、别名组列表，以及按原始行号的逐条核对（含归并后事件对与“同组内”标记）；
- 别名文本为空、某行不是 2 个字段、或同一行两个名称相同时，返回逐行校验错误；未出现在区间中的别名组也会列出并标注“未出现在区间中”。

**入口与访问地址**：`docker compose up -d --build` 启动后访问 **http://localhost:8080**，在首页“事件区间”下方的**“事件别名”**区粘贴别名（或点**“填入归并可行示例”/“填入归并矛盾示例”**，会自动填入配套区间与别名），点击**“别名归并核对”**即可——核对直接使用页面上方现有的区间文本，无需重复粘贴。编辑任一文本框后旧的归并结论自动清空。

示例（区间混用同一事件的不同名称；第 6 行为同组内区间）：

```
# 事件区间
起床,洗漱,10,30
盥洗,早饭,15,45
早饭,出门,20,60
出门,晨会,40,90
起床,开会,80,240
洗漱,盥洗,-5,5

# 事件别名
洗漱,盥洗
开会,晨会
```

结果：7 个事件名称归并为 5 个统一事件（洗漱=盥洗、开会=晨会），第 6 行同组内区间满足（0 ∈ [-5,5]），时间线按统一事件展示并附每组原名称。

接口用法（curl）：

```bash
curl -X POST http://localhost:8080/api/aliases \
  -H 'Content-Type: application/json' \
  -d '{
    "text": "起床,洗漱,10,30\n盥洗,早饭,15,45\n早饭,起床,10,20",
    "aliases": "洗漱,盥洗"
  }'
```

返回（节选：未归并时“洗漱”“盥洗”是两个事件、区间本身可行；归并后 起床→洗漱→早饭→起床 构成闭合负环，矛盾链保留原始区间行号与原始事件名，并附别名组）：

```json
{
  "status": "conflict",
  "conflict": {
    "steps": [
      { "from": "早饭", "to": "洗漱", "line": 2, "kind": "lower", "bound": 15,
        "row_a": "盥洗", "row_b": "早饭", "relation": "早饭−洗漱 ≥ 15" },
      { "from": "洗漱", "to": "起床", "line": 1, "kind": "lower", "bound": 10,
        "row_a": "起床", "row_b": "洗漱", "relation": "洗漱−起床 ≥ 10" },
      { "from": "起床", "to": "早饭", "line": 3, "kind": "lower", "bound": 10,
        "row_a": "早饭", "row_b": "起床", "relation": "起床−早饭 ≥ 10" }
    ],
    "weight_sum": -35,
    "closes_to": "早饭"
  },
  "groups": [
    { "representative": "洗漱", "members": ["洗漱", "盥洗"], "size": 2, "in_timeline": true }
  ],
  "alias_count": 1, "merged_group_count": 1,
  "event_count": 3, "original_event_count": 4, "line_count": 3,
  "within_group_lines": [], "within_group_count": 0
}
```

可解时 `status: "ok"`，`timeline` 每项含 `event`（统一事件名）、`minute` 与 `members`（该组原名称）；`differences` 逐条核对含原始行号、原始事件对、`merged_a/merged_b`（归并后事件对）与 `same_group`（同组内标记）。

## 行程可达性核对

除了核对“时间差区间是否自洽”，整理者还可能问：**按口述中的发生顺序，人能不能赶得及从一个地点到下一个地点？** 本模块把页面上的时间差区间与一张有向通行网络联立：

- **事件地点**：逐行填写 `事件,地点`（同一事件重复登记地点为错误）；
- **通行路段**：逐行填写有向的 `起点,终点,分钟`（**单向通行**，分钟为非负整数；同一起点→终点多行保留，求最短时取最小值；负通行时间为错误）；- **行程顺序**：**按发生顺序每行一个事件名**（同一事件重复出现为错误），继续沿用页面上方“事件区间”里的时间差区间（区间文本可留空，表示只核对通行）。

后端对每对**相邻行程事件**在地点网络中用 **Dijkstra** 求最短通行时间：

- **同地点按零分钟处理**（不经过任何路段）；地点不同但路网中没有有向路径时判为**无路可达**，逐段指出是第几个事件段（如“第 2 段：早饭→开会（餐馆→公司）无路可达”），在全部相邻段可达之前不做时间联立；
- 全部可达时，把每个“**后一事件 − 前一事件 ≥ 最短通行分钟**”作为通行下界，与原区间一起送入同一套**差分约束 Bellman-Ford**；
- **时间冲突**：联立出现负环时，返回含**原区间行号、事件段及其最短路线**的闭合矛盾链（通行下界环节标注“事件段 N · 通行下界 d”、地点对与逐路段路线）；原区间文本自身先矛盾时单独返回现有矛盾链，并注明尚未加入通行下界；
- **可行**：列出按发生顺序的**各事件段最短路线、所需（最短通行）分钟、时间线实际间隔与富余分钟**，以及一条满足**全部区间与通行下界**、以最早事件为第 0 分钟的时间线（含每个事件的地点）。

校验项：**重复事件地点**（同一事件登记两个地点，给出两处行号）、**缺失事件地点**（行程事件未在地点文本中登记）、**重复行程事件**（发生顺序中同一事件出现两次，给出两处行号）、**负通行时间**（路段分钟为负），以及地点/路段/行程/区间四类文本各自的字段与整数校验；所有错误都带对应文本的原始行号。

页面操作：在“事件区间”框粘贴时间差区间（或点示例按钮自动填入），在**“行程可达性核对”**区的三个框分别粘贴事件地点、通行路段、行程顺序，点击**“行程可达性核对”**；可点**“填入可行行程示例 / 填入时间冲突示例 / 填入无路可达示例”**一键填充配套数据。下方显示结论横幅、按发生顺序的时间线、各段最短通行对照表、逐段路线卡片（含每条路段的原始行号与分钟），冲突时另显示含原区间行号与事件段最短路线的矛盾链。编辑任一文本框后旧结论自动清空。

可行示例：

```
# 事件区间
起床,早饭,20,120
早饭,开会,30,120
起床,开会,60,300

# 事件地点
起床,家
早饭,餐馆
开会,公司

# 通行路段（有向）
家,餐馆,15
餐馆,公司,25
家,公司,60

# 行程顺序（每行一个事件）
起床
早饭
开会
```

结果：第 1 段 家→餐馆 最短 15 分钟（直达），第 2 段 餐馆→公司 最短 25 分钟；虽然有直达“家→公司 60 分钟”，两段合计 40 分钟更短。时间线取 起床=0、早饭=30、开会=60：各段实际间隔 30/30 分钟，均 ≥ 最短通行且落在对应区间内。

接口用法（curl）：

```bash
curl -X POST http://localhost:8080/api/itinerary \
  -H 'Content-Type: application/json' \
  -d '{
    "text": "起床,早饭,10,60\n早饭,开会,10,60\n起床,开会,0,30",
    "places": "起床,家\n早饭,餐馆\n开会,公司",
    "routes": "家,餐馆,15\n餐馆,公司,25\n家,公司,60",
    "itinerary": "起床\n早饭\n开会"
  }'
```

返回（节选：两段最短通行合计至少 40 分钟，但第 3 行要求 开会−起床 ≤ 30，闭合矛盾链同时含原区间第 3 行上界与两个事件段的通行下界）：

```json
{
  "status": "conflict",
  "travel_step_segments": [1, 2],
  "conflict": {
    "steps": [
```

## 有序事件最大统一间隔

整理者有时会问：**在保持某几个事件先后顺序的前提下，相邻环节最多能统一隔开多少分钟？** 本模块沿用首页“事件区间”文本，另在“有序事件最大统一间隔”区**按希望保持的先后顺序逐行填写事件名**（每行一个），求最大的非负整数 g。

**输入格式**：

- 事件区间：沿用页面上方“事件区间”文本（每行 `事件甲,事件乙,最少分钟,最多分钟`）；
- 事件顺序：每行一个事件名，**至少两个、互不相同、且已在区间文本中出现**；支持中文逗号 `，`；空行跳过但行号按原始文本计算；同一事件重复出现、不足两个事件、或事件未在区间中出现都会返回明确错误。

**求解规则**：对给定的 g，为每对相邻所选事件（前一事件 a、后一事件 b）加一条**间隔下界** `t(b) − t(a) ≥ g`，与全部原区间一起联立（同一套差分约束 Bellman-Ford）：

- **原区间语法错误 / 自身矛盾**：沿用现有逐行错误或闭合矛盾链（尚未加入间隔约束）；
- **顺序冲突**：原区间可行，但连 g=0（只保持先后、不要求间隔）都无法满足——返回含**顺序间隔环节**（标注相邻对序号）的闭合矛盾链；
- **无上限**：没有任何间隔约束落在约束环上（原区间对这些相邻间隔给不出任何上界），g 没有有限上限——显示**“无上限”**并给出 **g=0**（保持先后顺序）的一条可行时间线；
- **有界**：先指数放大再二分求出**最大的可行整数 g**，返回 g 与一条**达到该间隔的完整可行时间线**（满足全部原区间、每对相邻所选事件至少相隔 g 分钟，最早事件为第 0 分钟），并附相邻对间隔核对与原区间逐条核对。

页面操作：在“事件区间”框粘贴区间（或点“填入可行示例”），在**“有序事件最大统一间隔”**区按先后顺序逐行填写事件名（或点**“填入有界示例 / 填入无上限示例 / 填入顺序冲突示例”**一键填充配套数据），点击**“求最大统一间隔”**；下方显示结论横幅（g 值 / 无上限 / 顺序冲突）、相邻对间隔核对表、完整可行时间线与原区间逐条核对，顺序冲突时另显示含顺序间隔环节的矛盾链。编辑任一文本框后旧结论自动清空。

有界示例（配合“填入可行示例”的 6 行区间，顺序为 起床→早饭→开会）：

```

早饭

```

## 记录时钟对齐

口述记录常来自走时不一的多个时钟。整理者在首页“事件区间”之外，于**“记录时钟对齐”**区逐行填写：

```
来源,事件,本地分钟
```

含义：该来源在其本地时钟的“本地分钟”读到该事件。**首个非空行的来源为参考时钟**，其偏移固定为 **0**；同一来源的全部记录共用一个整数分钟偏移 `o(来源)`，满足：

```
事件真实分钟 = 本地分钟 + o(来源)
```

本地分钟为整数、可负；支持中文逗号 `，`；空行跳过但**行号按记录文本的原始行号**计算。后端把每条记录写成一对等式边（`时钟(来源) → 事件` 权为本地分钟、`事件 → 时钟(来源)` 权为其负值），与区间行的上、下界边一起跑同一套 Bellman-Ford（时钟节点为独立内部节点，来源与事件同名也不混淆）。偏移只以差值形式出现，故无需额外钉零即可检出全部负环：

- **冲突**：记录等式与区间共同矛盾时，返回含**区间行号或记录行号、所用界值**（本地分钟）的**闭合冲突链**（`source` 区分 `"interval"` / `"clock"`，链中“时钟(来源)”为该来源的偏移节点）；
- **可解**：以参考时钟为源跑前/反向最短路，给出每个来源相对参考时钟的**最紧偏移上下界**——两界相等为**精确**偏移，否则为**范围**；参考来源恒为精确 0；
- **未定位**：与参考来源互不连通的来源（及其事件）与参考时钟分属独立约束组件，任何具体偏移都只是任意平移，一律标为**“未定位”**，**不显示伪精确偏移**；
- 区间文本可留空（纯记录对齐模式）；另返回事件真实分钟范围与逐条记录核对（本地分钟 + 偏移推出的真实分钟范围）。

页面操作：在“事件区间”框粘贴区间（可留空），在**“记录时钟对齐”**框逐行粘贴 `来源,事件,本地分钟`（或点**“填入对齐示例”/“填入对齐矛盾示例”**一键填充配套数据），点击**“时钟对齐求解”**；下方显示结论横幅（参考时钟、已定位/未定位来源数）、**各来源偏移表**（参考/精确/范围/未定位）、**事件真实分钟范围表**与**逐条记录核对表**，冲突时另显示含区间行号与记录行号的闭合冲突链。编辑任一文本框后旧结论自动清空。

## 全局容差评估

当几句叙述互相矛盾时，整理者可能想知道：**所有说法整体还需要松动多少分钟才能自洽？** 本模块沿用首页“事件区间”文本，把每条有效区间 `[lo,hi]` 同时向两侧扩为 `[lo−k, hi+k]`（**k 为非负整数分钟，上下界各放宽 k**），求**使全部约束可解的最小 k**。

**求解规则**：放宽 k 分钟后，上界边权为 `hi+k`、下界边权为 `−lo+k`——闭合环上**每条边权都恰好增大 k**，故可行性随 k 增大单调变好；所有界值为整数，最小可行 k 也是整数。后端先试 k=0（原文已可行即返回 0），否则先指数放大（1、2、4、…）找到可行上界，再二分最小可行 k，全程复用同一套 Bellman-Ford。

- **k=0**：原文本无冲突，直接给出原文的一条可行时间线，每行原区间均满足；
- **k>0**：给出最小 k、一条**扩展后可行时间线**（最早事件为第 0 分钟）以及每行：原区间、扩展区间 `[lo−k, hi+k]`、下界/上界放宽量（均为 k）、本时间线实际差值、距扩展下界/上界的富余，以及原区间是否本来就满足（不满足的行高亮，即依赖统一放宽才成立的原始行）；
- **为何不能再缩小**：对 **k−1** 再联立一次并还原闭合冲突链，链中每环给出**原始行号、原界值与 k−1 时实际使用的扩展界值**；环上原界边权之和 W（< 0）、环长 L，则统一放宽 k 分钟后环权为 `W + L·k`，要其 ≥ 0 必须 `k ≥ ⌈−W/L⌉`——该值恰好等于求出的最小 k，而 k−1 时环权仍为负（响应中给出 `weight_sum`），形成不可再缩小的直接证据；
- **空约束集视为可行**（k=0、空时间线）；语法错误沿用首页逐行报错（含原始行号）；
- **大整数分钟全程精确**：分钟可以是任意大的整数（如 `9007199254740993`）。后端用 Python 任意精度整数求解，**不截断、不转浮点、不拒绝合法大整数**；接口返回中所有**分钟字段**（k、时间线 `minute`、`low/high`、`expanded_low/expanded_high`、`low_shift/high_shift`、`actual`、`lower_slack/upper_slack`、冲突链的 `weight/bound/original_bound/expanded_bound/slack`、`weight_sum/original_weight_sum/slack_tested/required_k`）一律为**十进制字符串**，**计数与行号**（`total_lines/event_count/line/cycle_length`）保持**数值**；前端用 **BigInt** 按整数计算扩展区间、富余与 `⌈−W/L⌉` 公式后再展示，表格、公式与文字证明保持一致。

页面操作：在“事件区间”框粘贴文本（或点**“填入无需放宽示例 / 填入需放宽示例”**），在**“全局容差评估”**区点击**“求最小容差”**；下方显示结论横幅（最小 k）、扩展后可行时间线、每行原区间与扩展区间实际差值对照表；k>0 时另显示 k−1 时的闭合冲突链（原界 → 扩展界标注）与“⌈−W/L⌉ = k”的算术说明。编辑区间文本后旧结论自动清空。

其他情形：原文已可行时 `k` 为 `"0"`、`blocking_conflict` 为 `null`、每行 `fits_original` 为 `true`；空文本时 `total_lines` 为 0、`timeline` 为空数组；语法错误返回 `status: "error"` 与逐行错误（含原始行号）。

## 绝对时间锚定

整理者在区间文本旁的“绝对时间锚点”框中粘贴多行锚点，每行一条：

```
事件名,YYYY-MM-DD HH:MM
```

含义：该事件发生在指定的绝对时刻。日期按**同一无时区的本地时间**处理，精确到分钟；后端把每个锚点换算为相对**统一零点**（公历 0001-01-01 00:00）的分钟数，作为**事件相对零点的等式**与区间行一起联立（复用同一套差分约束与 Bellman-Ford）：

- **同名锚点重复也参与判定**：同一事件的两条锚点等式互相校验，时刻不同即构成冲突；
- **冲突**：锚点与区间、或锚点彼此矛盾时，返回含**区间行号、锚点行号与所用界值**的闭合矛盾链（链上零点节点显示为“统一零点”）；
- **可解**：只为**与锚点连通**的事件显示绝对日期时刻——其余约束推出的最紧下界/上界相等时为**精确**时刻，否则为**范围**；与任何锚点都不连通的事件标为**“未定位”**，**不把任何任意平移量当作真实日期**；
- 区间文本可留空（纯锚点模式），锚点文本为空时报错提示。

页面操作：在“事件区间”框粘贴区间（或点“填入可行示例”），在“绝对时间锚点”框粘贴锚点（或点“填入锚点示例”，区间框为空时会自动填入可行示例配合演示），点击**“锚定求解”**；下方显示统计横幅、各事件的绝对时刻表（精确/范围/未定位）与本次使用的锚点列表。编辑任一文本框后旧的锚定结果自动清空。

## 约束冗余核对

整理者在文本中**任选一条原始行**，后端删去该行对应的上、下界两条约束后，在其余约束上求这两个事件时间差的**最紧下界与上界**：

- 推不出的端点标为**无界**（`null`）；
- 有界端点给出**推导路径**：路径上每一环都标注**原始行号、所用界（上界/下界）与界值**；
- 判定规则：推导区间**完全落在**所选行区间内（推导下界 ≥ 原下界 且 推导上界 ≤ 原上界）⇒ **可删**；任一端点无界或超出 ⇒ **必要**；
- 输入无效或原约束互相冲突时，接口直接返回现有 `/api/solve` 的求解结果（错误列表或矛盾链）。

页面操作：粘贴文本后，在“约束冗余核对”区的下拉框中选择一条原始行（选项即原始行号与行内容），点击**“核对所选行”**，下方即显示结论横幅（可删/必要）、区间对比表与两个端点的推导路径链图及明细表。

示例：点“填入可行示例”后，第 5 行 `起床,开会,80,240` 与第 6 行 `起床,早饭,25,90` 均会被判为**可删**（第 5 行由第 1–4 行推出 [85, 225] ⊆ [80, 240]）；第 1–4 行则为**必要**。

## 冲突单行修订建议

文本**语法有效但联立矛盾**时，后端遍历每条原始约束行，**逐行暂时移除该行的上、下界约束**后对其余行重新联立：

- **其余行仍矛盾** ⇒ 该行排除（只改它一个端点救不回其余行自身的矛盾）；
- **其余行可解** ⇒ 复用冗余核对同款最短路推导，求出其余约束对这两个事件时间差的**最紧可行区间** `[推导下界, 推导上界]`，然后只放宽该行**一个端点**至**首次相交的整数分钟**：
  - 上界冲突（推导上界 < 原下界）：只把**下界**放宽到推导上界，改动 `原下界 − 推导上界` 分钟；
  - 下界冲突（推导下界 > 原上界）：只把**上界**放宽到推导下界，改动 `推导下界 − 原上界` 分钟；
  - 区间含整数端点，移到边界即首次相交，改动量最小；另一个端点保持不动。

每条建议给出：**最小改动分钟数、替换后的整行**（事件名与原行号不变，只换一个端点），以及**迫使该端点移动的原始行号与界值推导链**（推出那个紧界的最短路路径，每环标注原始行号、所用界与界值）。建议按**改动分钟数、原始行号**升序排序；没有任何单行修复时明确提示“没有单行修复方案”。输入未通过校验时返回逐行错误；原文本可解时明确说明**无需修订**。

页面操作：粘贴矛盾文本（或点“填入矛盾示例”）后，点击“冲突单行修订建议”区的**“获取修订建议”**，下方逐条显示建议卡片（改动量、替换后的整行、推导链链图与明细表）；点击卡片上的**“填入此建议”**会把替换后的整行写回上方文本框对应原始行号并自动重新联立确认可解；**编辑文本后旧建议自动清空**。

接口用法（curl）：

```bash
curl -X POST http://localhost:8080/api/repair \
  -H 'Content-Type: application/json' \
  -d '{"text": "早饭,开会,30,60\n开会,晚饭,45,90\n晚饭,早饭,20,50"}'
```

返回（节选，矛盾示例的三条建议改动量相同，按行号排序）：

## 两版比较

整理者把口述稿的**基准版**与**修订版**区间文本分别粘贴到两个文本框，点击**“比较两版”**。后端对两版**完全独立**地执行现有解析与联立求解（复用同一套 `parse_text` 与 Bellman-Ford 逻辑），再以**基准中首次出现的共同事件**作为两版**共享参考事件**进行比较：

- **共享参考**：取基准文本中**首次出现**、且在两版中都存在的事件为参考事件（两版用同一个事件，而不是各按本版最早事件归零）；
- **比较最紧区间而非样本时刻**：对每个共同事件，在两版中分别求它**相对参考事件**的时间差**最紧下界与上界**（参考→事件最短路为上界、事件→参考最短路取负为下界，复用冗余核对同款推导）。**任一端点（下界或上界）在两版间不同才把该事件计为变化**——绝不比较两版各自“最早事件为第 0 分钟”的样本时刻：新增事件会改变另一版的归零原点，样本时刻差只是整体平移假象。例如基准 `A,B,10,10`、修订增加 `C,A,5,5` 时，A、B 相对 A 的区间仍为 `[0,0]` 与 `[10,10]`，两事件**均未变**，C 只是新增事件；
- **端点差值**：表格列出每个共同事件在基准与修订中的最紧区间，以及**下界差值**、**上界差值**（修订界 − 基准界，正数表示界变大、负数表示界变小；某一端在一版中无界时显示“界 ↔ −∞/+∞”迁移）。例如 `A,B,10,20` 改为 `A,B,10,15` 时，B 的下界同为 10（差值 0），上界 20→15（**−5 分钟**），B 计为变化；
- **变化端点证据**：对每个变化端点，分别给出**基准版与修订版各自**的**原始行号、所用界值与连续推导路径**（链图 + 明细表），修订版路径上的每环另标注该行相对基准是**“已修改 / 新增 / 区间未改”**；端点在某一版中无界时，该版区块说明无任何推导路径；
- **不可比**：事件在**任一版**中两个方向都与参考事件不通（分属互不连通的约束组件）时标为**“不可比”**，**隐藏端点差值与变化证据**（仍可显示各版能推出的区间，不连通的一版为“—”）；
- **新增 / 删除事件**：仅修订版出现的事件标为**新增**、仅基准版出现的标为**删除**，并给出其在所在版本中相对参考事件的最紧区间（不连通或无参考时为“—”）；**没有共同事件时不做区间比较，只列新增、删除**；
- **失败不产生差异**：任一版校验无效（逐行错误）或存在闭合矛盾链（负环）时，接口返回 `status: "invalid"`，在 `base` / `revised` 字段中**分别**带回该版与 `/api/solve` 完全相同的错误列表或矛盾链，页面左右两栏分别展示，**不生成对齐表或差异结论**；
- 任一输入框内容变化时，页面立即**清空旧的比较结果**，避免展示与输入不一致的结论。

页面操作：在“两版比较”区两个文本框中分别粘贴（或点**“填入两版示例”**），点击**“比较两版”**；下方显示统计横幅、**共同事件区间对照表**（类型 / 事件 / 基准区间 / 修订区间 / 下界差值 / 上界差值 / 变化端点与两版所用行）以及每个变化端点的**证据卡片**（基准版、修订版各一栏的推导路径链图与明细表）。

## 互斥说法下的先后查询

同一事件的经过常有多种互相矛盾的说法。整理者把**所有说法都认可的约束**留在“事件区间”文本中作**共同约束**，把**只能二选一的说法**按行填入“互斥说法候选组”，再指定要查询先后关系的两个事件，后端枚举全部取舍组合后给出稳健结论。

**输入格式**：

- 共同约束：沿用“事件区间”文本（每行 `事件甲,事件乙,最少分钟,最多分钟`）；
- 候选组：每行 `区间A | 区间B`，两侧均沿用同一区间格式，表示该行的两条说法**只能选一条**；**最多 6 行**（每行二选一，组合数为 2 的幂，限制行数保证枚举耗时可控）；支持中文逗号 `，` 与中文竖线 `｜`；空行跳过但行号按原始文本计算；
- 查询事件：填写**事件甲**与**事件乙**，两者**必须出现在共同约束中**（且不能相同）。

**判定规则**：枚举全部 `2^N` 个“每组选一侧”的组合，分别与共同约束联立（同一套差分约束 Bellman-Ford），存在负环的组合判为**冲突组合**并排除；对每个**可行组合**复用冗余核对同款最短路推导求 `t(乙) − t(甲)` 的**最紧下界/上界**（推不出的端点为无界），再跨组合合并——**下界取各组合最小值、上界取各组合最大值，任一组合对应端无界则合并端无界**：

- 合并下界 **≥ 1 分钟** ⇒ **甲始终先于乙**（无论互斥说法如何取舍）；
- 合并上界 **≤ −1 分钟** ⇒ **甲始终后于乙**；
- 其余 ⇒ **不确定**；
- **无可行组合 ⇒ 不作先后判断**。

页面操作：在“事件区间”框粘贴共同约束（或点“填入可行示例”），在“互斥说法下的先后查询”区填写查询事件甲、乙与候选组（或点**“填入互斥示例”**，共同约束为空时自动填入可行示例配合演示），点击**“先后查询”**；下方显示结论横幅、**可行/冲突组合数与合并区间**、候选组对照表与逐组合明细（每组所选一侧、联立结果、可行组合的最紧区间）。编辑任一相关输入后旧结论自动清空。

```bash
    "groups": "开会,起床,-400,-300 | 起床,开会,80,240\n早饭,午休,5,15 | 出门,午休,5,15",
```

```json
                             { "line": 2, "side": "A", "a": "早饭", "b": "午休", "low": 5, "high": 15 } ],
      "feasible": false, "low": null, "high": null },
    { "index": 3, "picks": [ { "line": 1, "side": "B", "a": "起床", "b": "开会", "low": 80, "high": 240 },
                             { "line": 2, "side": "A", "a": "早饭", "b": "午休", "low": 5, "high": 15 } ],
      "feasible": true, "low": 85, "high": 225, "lower_bounded": true, "upper_bounded": true }
  ]
}
```

`verdict` 取值：`before`（甲始终先于乙）/ `after`（甲始终后于乙）/ `undetermined`（不确定）/ `no_feasible`（无可行组合，不作先后判断，此时 `merged_low/merged_high` 为 `null`）。查询事件未出现在共同约束中、候选组超过 6 行或格式错误时返回 `status: "error"` 与逐条错误。

## 最少撤回

几句叙述实在无法同时成立时，整理者往往想知道“**最少撤回哪几行**，剩下的就能自洽”。本模块直接使用页面上方“事件区间”文本（现有 `事件甲,事件乙,最少分钟,最多分钟` 格式），后端复用同一套区间解析与差分约束联立求解：

- **输入限制**：最多 **10 条非空行**（空行跳过、行号按原始文本计算）；搜索按撤回行数枚举全部行号组合，组合数随行数快速增长，限 10 条保证耗时可控，超限返回明确错误；
- **搜索规则**：先检查原文本身（撤回 0 行）；不可行时按撤回行数 `k = 1, 2, …` 递增枚举 `C(n, k)` 个原始行号组合，对每个组合把其余行重新联立（同一套 Bellman-Ford），**第一个存在可行剩余子集的 k 即最少撤回数**，返回该层**全部**可行组合；
- **空约束集视为可行**：空文本（或只有空行）直接返回零撤回方案与空时间线；撤回全部行时方案的时间线为空；
- **原文已可行**：返回零撤回方案，时间线即原文的规范化可行解；
- **每个方案**展示撤回的原始行号、保留行数，以及剩余约束的**一条可行时间线**（以最早事件为第 0 分钟）；原文矛盾时另附原始闭合矛盾链（页面上可展开查看）。

页面操作：在“事件区间”框粘贴文本（或点“最少撤回”区的**“填入撤回示例”**——前 3 行构成闭合负环、第 4 行与冲突无关，撤回前 3 行中任意 1 行即恢复可行），点击**“最少撤回搜索”**；下方显示结论横幅（最少撤回行数、方案数、检查的组合数）、每个方案的撤回行对照表与剩余约束可行时间线，以及可展开的原始矛盾链。编辑文本后旧结论自动清空。

接口用法（curl）：

```bash
curl -X POST http://localhost:8080/api/withdrawals \
  -H 'Content-Type: application/json' \
  -d '{"text": "早饭,开会,30,60\n开会,晚饭,45,90\n晚饭,早饭,20,50\n睡觉,起床,360,480"}'
```

返回（节选：最少撤回 1 行，共 3 个方案；方案 1 撤回第 1 行后，剩余 3 行可行，时间线含与冲突无关的“睡觉→起床”链）：

## 原理简介

对每行 `甲,乙,lo,hi` 建立两条最短路约束：

- `t乙 − t甲 ≤ hi`：边 `甲 → 乙`，权 `hi`（上界）
- `t甲 − t乙 ≤ −lo`：边 `乙 → 甲`，权 `−lo`（下界）

再加一个指向所有事件、权为 0 的虚拟源（实现上等价于所有距离初始化为 0），运行 Bellman-Ford：

- 第 N 轮仍能松弛 ⇒ 存在负环，沿前驱指针还原负环，并映射回每条边的**原始行号与上/下界值**，即页面展示的闭合矛盾链（环上权值之和 < 0，意味着推出 `0 < 0` 式的矛盾）；
- 否则得到一组可行时刻，整体平移令最小值为 0，即为“最早事件在第 0 分钟”的时间线。

**冗余核对的推导**：删去所选行的两条边后，以单源 Bellman-Ford 求最短路——

- `甲 → 乙` 最短路 = 其余约束能推出的 `t乙 − t甲` **最紧上界**（不可达 ⇒ 上界无界）；
- `乙 → 甲` 最短路取负 = 其余约束能推出的 `t乙 − t甲` **最紧下界**（不可达 ⇒ 下界无界）；
- 最短路经前驱指针还原为推导路径，路径上每条边映射回**原始行号与所用界值**，作为页面展示的证据。

**两版比较的对齐与证据**：两版文本分别走同一套“解析 → Bellman-Ford”流程（但**不**各自平移归零再比较）：取基准文本中首次出现的共同事件作两版共享参考事件，对每个共同事件分别在两版图上用冗余核对同款单源最短路求它相对参考事件的最紧区间——参考→事件最短路为最紧上界、事件→参考最短路取负为最紧下界，最短路经前驱指针还原为**连续推导路径**。只有下界或上界在两版间不同才把事件计为变化；变化端点同时给出两版各自的界值、路径上的原始行号与所用界值（修订版路径另标注行相对基准新增/已修改/区间未改）。某一版中两个方向都不可达的事件标为不可比，不输出端点差值与证据；没有共同事件时只列新增、删除；任一版错误或负环时短路返回该版结果，不构造对齐结论。

**冲突单行修订建议的推导**：对每条原始行，删去其两条边后对其余行运行 Bellman-Ford——仍有负环则跳过该行；可解时用与冗余核对相同的两条单源最短路求出这两个事件时间差的最紧可行区间 `[dl, dh]`。`dh < 原下界` 时只把下界放宽到 `dh`（证据为推出最紧上界的路径），`dl > 原上界` 时只把上界放宽到 `dl`（证据为推出最紧下界的路径）；区间含整数端点，移到边界即首次相交的整数分钟，改动量最小。

**绝对时间锚定的联立**：每个锚点 `事件名,YYYY-MM-DD HH:MM`（同一无时区本地时间）换算为相对统一零点（0001-01-01 00:00）的分钟数 `M`，引入零点节点 ZERO 与一对等式边——`ZERO → 事件` 权 `M`（不晚于锚定时刻）、`事件 → ZERO` 权 `−M`（不早于锚定时刻），与区间行的上、下界边一起跑同一套 Bellman-Ford；同名锚点重复即两条等式互查，时刻不同自然形成负环。负环还原时锚点边映射回**锚点行号与锚定时刻**，区间边映射回**区间行号与上/下界值**，构成闭合矛盾链。可解时不取任何平移后的可行解充当日期：对每个事件用冗余核对同款单源最短路求其相对零点的最紧下界/上界（`ZERO→事件` 最短路为上界，`事件→ZERO` 最短路取负为下界），两端都有界（与锚点连通）才显示绝对日期时刻——两界相等为精确点，否则为范围；不连通的事件标为“未定位”。

**互斥说法下的先后查询**：候选组每行解析为两条互斥说法（复用区间行同款四字段校验），枚举全部 `2^N`（N ≤ 6）个“每组选一侧”的组合；每个组合 = 共同约束 + 各组所选一侧，走同一套建边与 Bellman-Ford——存在负环的组合判为冲突并排除。对每个可行组合，复用冗余核对同款 `_derive_bound` 最短路求 `t(乙) − t(甲)` 的最紧上界（`甲→乙` 最短路）与最紧下界（`乙→甲` 最短路取负），不可达的端点为无界。跨组合合并：下界取最小、上界取最大，任一组合对应端无界则合并端无界；合并下界 ≥ 1 判“甲始终先于乙”，合并上界 ≤ −1 判“甲始终后于乙”，否则不确定，无可行组合不作判断。

**最少撤回**：对最多 10 条非空有效约束，先试撤回 0 行（原文本身）；不可行时按撤回行数 `k = 1, 2, …` 递增枚举 `C(n, k)` 个原始行号组合，每个组合删去对应行的上、下界边后对其余行走同一套 Bellman-Ford——第一个存在可行剩余子集的 `k` 即最少撤回数，返回该层全部可行组合；每个方案的剩余约束经同一套“平移到最早事件为第 0 分钟”的规范化得到一条可行时间线，撤回全部行时为空约束集（视为可行），时间线为空。

**事件别名归并核对**：别名行 `事件名,同一事件的另一名称` 经并查集按传递关系归组（A=B、B=C ⇒ A、B、C 同组），每组取区间文本中最先出现的名称作统一事件名；区间行两端替换为统一事件名（行号保留为原始行号）后走同一套建边与 Bellman-Ford。两端归并为同一事件的区间行成为自环边照常参与判定：上界边权 `hi`、下界边权 `−lo`，`hi < 0` 或 `lo > 0` 即自身构成负环（等价于要求 0 落在该行区间内）。负环还原的矛盾链保留原始区间行号，每环另附该行原始事件名，并随结果返回别名组（统一事件名与组内原名称）；可解时按统一事件输出归并时间线，每个节点附该组原名称。

**行程可达性核对**：地点行 `事件,地点`、有向路段行 `起点,终点,分钟`（非负）与按发生顺序排列的事件名各自逐行校验后，对每对相邻行程事件在地点有向图上跑 **Dijkstra**（边权非负，重复有向路段取最短；等距离路线按节点序列字典序、再按路段行号决胜，结果确定），同地点直接取 0 分钟。任一段无路可达即逐段指出、不联立；全部可达时，为每段加一条差分约束边 `后一事件 → 前一事件`、权 `−最短通行分钟`（即 t(后) − t(前) ≥ 通行分钟），与区间行的上、下界边一起跑同一套 Bellman-Ford。负环还原时通行边映射回**事件段序号、地点对与最短路线**（逐路段含原始路段行号与分钟），区间边仍映射原区间行号与界值，构成同时含两类依据的闭合矛盾链。可行解整体平移令最早事件为 0，即一条同时满足全部区间与通行下界的时间线；逐段再用相邻事件时刻之差给出实际间隔与相对最短通行的富余。

**有序事件最大统一间隔**：对给定的非负整数 g，为每对相邻所选事件（前 a、后 b）加一条间隔下界边 `b → a`、权 `−g`（即 t(b) − t(a) ≥ g），与区间行的上、下界边一起跑同一套 Bellman-Ford——可行性随 g 增大单调变差，且所有界值都是整数，故最大可行 g 也是整数。先联立原区间：自身矛盾时直接沿用现有闭合矛盾链；再试 g=0：不可行即顺序冲突（负环必含至少一条间隔边，还原为含顺序间隔环节的闭合矛盾链）。有界性判定：某条间隔边 `b → a` 落在环上当且仅当图中 a 可达 b（间隔边只从后选事件指向前选事件，任何含间隔边的环必含区间边）；没有任何间隔边在环上时任意大的 g 都不会产生负环，即**无上限**，按约定给出 g=0 的可行时间线。有界时先指数放大（1、2、4、…）找到不可行的上界，再在 `(可行, 不可行]` 间二分最大的可行整数 g，最后在该 g 下联立并整体平移令最早事件为 0，得到一条达到该间隔的完整可行时间线。

**记录时钟对齐**：记录行 `来源,事件,本地分钟 m` 引入两类变量——事件真实分钟 t(事件) 与每个来源一个整数分钟偏移 o(来源)（时钟节点为带内部前缀的独立节点，来源与事件同名也不混淆），并写成一对等式边：`时钟(来源) → 事件` 权 `m`（t(事件) − o(来源) ≤ m）与 `事件 → 时钟(来源)` 权 `−m`（t(事件) − o(来源) ≥ m），与区间行的上、下界边一起跑同一套 Bellman-Ford。首个来源为参考时钟、偏移固定为 0，但偏移只以差值形式参与所有约束，故无需额外钉零即可检出全部负环。负环还原时记录等式边映射回**记录行号与本地分钟**（链上显示“时钟(来源)”节点），区间边仍映射原区间行号与界值，构成同时含两类依据的闭合冲突链。可解时以参考时钟节点为源跑前向最短路（最紧上界）、在反向图上再跑一次（距离取负为最紧下界）：两端都有界（与参考时钟连通）才给出偏移或事件真实分钟——两界相等为精确点，否则为范围；未连通来源标为“未定位”，不显示伪精确偏移。

**全局容差评估**：统一放宽 k 分钟把每行 `[lo,hi]` 变为 `[lo−k,hi+k]`：上界边权 `hi+k`、下界边权 `−lo+k`，于是任意闭合环的环权都比原界环权多 `L·k`（L 为环长）——可行性随 k 单调变好，最小可行 k 必为整数。先试 k=0；不可行时指数放大（1、2、4、…）找可行上界再二分最小可行 k，每个候选只跑同一套 Bellman-Ford。最小性证明直接取 k−1 时还原出的负环：其原界环权 W<0、环长 L，则 k 必须满足 `W + L·k ≥ 0`，即 `k ≥ ⌈−W/L⌉`；该环在 k−1 时环权 `W+L(k−1)<0` 而在 k 时非负，故 `⌈−W/L⌉ = k`。矛盾链每环映射回**原始行号、原界值与 k−1 时所用扩展界值**；可行时间线经同一套“平移到最早事件为第 0 分钟”规范化得到，并逐行给出原区间/扩展区间与实际差值及两端富余。分钟可为任意大整数：求解全程任意精度整数，`/api/tolerance` 返回的所有分钟字段以**十进制字符串**传输（计数与行号保持数值），前端按 **BigInt** 整数运算后展示，超出 JS 安全整数范围的分钟（如 `9007199254740993`）也不会丢失精度。

## API

- `GET /` — 页面
- `GET /api/health` — 健康检查
- `POST /api/solve` — 请求体 `{"text": "甲,乙,30,60\n..."}`，返回：
  - `status: "ok"`：`timeline`（事件与分钟）、`differences`（逐条核对）；
  - `status: "conflict"`：`conflict.steps`（矛盾链每一环的行号、方向、上/下界与含义）；
  - `status: "error"`：`errors`（逐行校验错误，含原始行号）。
- `POST /api/redundancy` — 请求体 `{"text": "...", "line": 5}`（`line` 为原始行号），返回：
  - `status: "ok"`：`verdict`（`"removable"` 可删 / `"necessary"` 必要）、所选行 `a/b/low/high`、推导区间 `derived_low/derived_high`（无界端点为 `null`，另有 `lower_bounded/upper_bounded` 布尔标记）、有界端点的推导路径 `lower_path/upper_path`（每环含 `line` 原始行号、`kind`/`kind_label` 所用界、`bound` 界值、`relation` 含义）；
  - `status: "conflict"` / `status: "error"`：与 `/api/solve` 完全相同的现有求解结果（原约束冲突或输入无效时沿用）。
- `POST /api/compare` — 请求体 `{"base": "...", "revised": "..."}`，两版各自独立解析与联立：
  - `status: "ok"`：`reference`（两版共享参考事件，即基准中首次出现的共同事件；无共同事件时为 `null`），`base`/`revised` 各含 `event_count/line_count`，计数 `common_count/comparable_count/changed_count/added_count/removed_count/incomparable_count`，以及 `alignment` 对齐列表：
    - 共同事件（两版均与参考连通）：`kind: "common"`、`is_reference`，两版界值 `base_low/base_high/revised_low/revised_high`（无界端点为 `null`）、端点差值 `low_delta/high_delta`（两端在两版中都有界时为修订界 − 基准界，否则为 `null`）、`low_changed/high_changed/changed`；`changed` 时带 `evidence`：`lower`/`upper` 仅对变化端点非空，各含 `base`/`revised` 两版的 `bound`（该端点界值，无界为 `null`）、`bounded`、`lines`（路径所用原始行号，去重保序）与 `path`（连续推导路径每环的行号、所用界、界值、含义；修订版路径另含 `change`：`added`/`changed`/`unchanged`）；
    - 不可比共同事件：`kind: "incomparable"`（任一版中与参考事件两个方向都不通），`low_delta/high_delta` 为 `null`、`evidence` 为 `null`，两版界值字段随连通情况返回（不连通的一版端点为 `null`）；
    - 新增 / 删除：`kind: "added"` / `"removed"`，仅所在版本的 `revised_low/revised_high` 或 `base_low/base_high` 有值（相对参考的最紧区间，不连通或无参考时为 `null`）；
  - `status: "invalid"`：不生成差异结论；`base`/`revised` 分别为该版完整求解结果——`status: "error"` 带逐行 `errors`（含原始行号），或 `status: "conflict"` 带闭合矛盾链；另一版若可解则带与 `/api/solve` 相同的 `timeline/differences`。
- `POST /api/repair` — 请求体 `{"text": "..."}`，复用现有解析与求解给出冲突单行修订建议：
  - `status: "conflict"`：`conflict`（与 `/api/solve` 相同的闭合矛盾链）、`checked_lines`（尝试过的行数）、`suggestion_count` 与 `suggestions` 建议列表（按改动分钟数、原始行号升序；每条含 `line` 原始行号、`a/b/low/high` 原行区间、`endpoint`/`endpoint_label` 被放宽的端点、`old_value/new_value`、`change_minutes` 最小改动分钟数、`new_line` 替换后的整行、`derived_low/derived_high` 其余行推导的最紧可行区间、`forcing_lines` 迫使该端点移动的原始行号、`forcing_path` 界值推导链——每环含行号、所用界、界值与含义）；`suggestions` 为空即无单行修复方案；
  - `status: "ok"`：原文本无冲突，`message` 说明无需修订；
  - `status: "error"`：`errors`（逐行校验错误，含原始行号）。
- `POST /api/anchor` — 请求体 `{"text": "区间文本", "anchors": "锚点文本"}`（锚点每行 `事件名,YYYY-MM-DD HH:MM`，同一无时区本地时间；区间文本可留空为纯锚点模式）：
  - `status: "ok"`：`anchors`（解析后的锚点：`line` 锚点行号、`event`、`time` 规范化时刻、`minute` 相对零点分钟数）、`events`（每个事件 `located` 是否与锚点连通；连通时 `minute_low/minute_high` 相对零点的最紧界、`abs_low/abs_high` 对应日期时刻文本、`exact` 是否精确点，未连通时均为 `null`）、计数 `event_count/located_count/anchor_count/line_count`；
  - `status: "conflict"`：`conflict.steps` 闭合矛盾链，每环含 `source`（`"interval"` 区间行 / `"anchor"` 锚点行）、`line` 对应文本的原始行号、`kind`/`kind_label`（上界/下界/锚点）、`bound` 界值（锚点环另有 `anchor_time` 日期时刻文本）、`relation` 含义；
  - `status: "error"`：`errors`（区间行错误与锚点行错误合并，锚点错误以“锚点第N行”前缀标注）。
- `POST /api/precedence` — 请求体 `{"text": "共同约束区间文本", "groups": "区间A | 区间B\n…（最多 6 行）", "a": "事件甲", "b": "事件乙"}`（甲、乙须出现在共同约束中）：
  - `status: "ok"`：`group_count`（候选组数）、`combination_count`（组合总数）、`feasible_count`/`conflict_count`（可行/冲突组合数）、`merged_low`/`merged_high`（跨组合合并区间，端点无界时为 `null`，另有 `lower_bounded/upper_bounded` 布尔标记）、`verdict`/`verdict_label`（`before` 甲始终先于乙 / `after` 甲始终后于乙 / `undetermined` 不确定 / `no_feasible` 无可行组合不作判断）、`groups`（解析后的候选组：行号与 A/B 两侧说法）、`combinations`（逐组合明细：`picks` 各组所选一侧、`feasible`、可行组合的 `low/high` 最紧界与有界标记）；
  - `status: "error"`：`errors`（共同约束行错误、候选组错误——以“候选组第N行A/B侧”前缀标注——与查询事件校验错误合并，含原始行号）。
- `POST /api/withdrawals` — 请求体 `{"text": "区间文本"}`（现有区间格式，最多 10 条非空行），按撤回行数递增搜索最少撤回组合：
  - `status: "ok"`：`minimum`（最少撤回行数）、`total_lines`（有效约束行数）、`checked_combinations`（检查过的撤回组合数）、`message`（结论文案）、`original_feasible`（原文是否已可行）、`plans`（全部最少撤回方案：每个含 `index` 方案序号、`withdraw_count` 撤回行数、`withdrawn_lines` 撤回的原始行号、`remaining_count` 保留行数、`timeline` 剩余约束的一条可行时间线——撤回全部行时为空数组）；原文矛盾时另带 `conflict`（与 `/api/solve` 相同的闭合矛盾链）；空文本视为可行的空约束集，返回零撤回方案与空时间线；
  - `status: "error"`：`errors`（逐行校验错误，含原始行号；非空行超过 10 条时带超限提示）。
- `POST /api/aliases` — 请求体 `{"text": "区间文本", "aliases": "事件名,同一事件的另一名称\n..."}`，别名按传递关系归并后用归并节点联立原区间：
  - `status: "ok"`：`timeline`（归并后的可行时间线，每项含 `event` 统一事件名、`minute`、`members` 该组原名称）、`groups`（别名组：`representative` 统一事件名、`members` 组内原名称、`size`、`in_timeline` 是否出现在区间中）、`differences`（逐条核对：`line` 原始行号、`a/b` 原始事件对、`merged_a/merged_b` 归并后事件对、`low/high/actual`、`same_group` 同组内标记）、计数 `alias_count/merged_group_count/event_count/original_event_count/line_count` 与 `within_group_lines/within_group_count`（同组内区间行号与数量）；
  - `status: "conflict"`：`conflict.steps` 闭合矛盾链（`line` 为**原始区间行号**，每环另附 `row_a/row_b` 该行的**原始事件名**，`from/to` 为归并后的统一事件名），并带与 `"ok"` 相同的 `groups` 与计数；
  - `status: "error"`：`errors`（区间行错误与别名行错误合并，别名错误以“别名第N行”前缀标注）。
- `POST /api/itinerary` — 请求体 `{"text": "区间文本（可留空）", "places": "事件,地点\n…", "routes": "起点,终点,分钟\n…", "itinerary": "事件名（每行一个，按发生顺序）"}`，把相邻行程事件的地点网络最短通行（Dijkstra，同地点零分钟）作为下界与原区间联立：
  - `status: "ok"`：`timeline`（每项 `event/place/minute`）、`ordered_itinerary`（按发生顺序）、`segments`（每段 `from_event/to_event`、`from_place/to_place`、`same_place`、`reachable`、`travel_minutes`、逐路段 `route`（每段含路段原始 `line/from/to/minutes`）、时间线 `actual_minutes/slack_minutes` 与直接覆盖该段的 `interval_lines`）、`differences`（原区间逐条核对）及计数；
  - `status: "unreachable"`：`unreachable_segments`/`unreachable_count`（无路可达的事件段序号）与全部 `segments`（可达段仍含最短路线），不做时间联立；
  - `status: "conflict"`：`conflict.steps` 闭合矛盾链，区间环为原区间行号与上/下界，通行环为 `kind: "travel"`、`line: null`，另带 `segment`（事件段序号）、`from_event/to_event`、`from_place/to_place`、`travel_minutes` 与该段 `route`；并带 `travel_step_segments` 与全部 `segments`；
  - `status: "interval_conflict"`：区间文本自身矛盾，`conflict` 为与 `/api/solve` 相同的闭合矛盾链（尚未加入通行下界），另带 `segments` 供参考；
  - `status: "error"`：`errors`（区间、地点、路段、行程四类逐行错误合并；重复事件地点、缺失事件地点、重复行程事件、负通行时间均在此返回，含各文本原始行号）。
- `POST /api/max-gap` — 请求体 `{"text": "区间文本", "order": "事件名（每行一个，按希望保持的先后顺序）"}`（至少两个、互不相同、已在区间中出现），求最大的非负整数 g 使每对相邻所选事件至少相隔 g 分钟且全部原区间同时成立：
  - `status: "ok"`：`g`（最大统一间隔分钟数）、`bounded: true`、`timeline_g`（返回时间线所用的 g，即 g 本身）、`order`（所选顺序）、`gaps`（每对相邻所选事件的 `position/from/to` 与时间线实际间隔 `actual`）、`timeline`（达到该间隔的完整可行时间线，每项 `event/minute`，最早事件为第 0 分钟）、`differences`（与 `/api/solve` 同口径的逐条区间核对）及计数；
  - `status: "unbounded"`：g 无有限上限——`g` 为 `null`、`bounded: false`、`timeline_g` 为 0，`timeline/gaps/differences` 为 g=0（保持先后顺序）的一条可行时间线；
  - `status: "order_conflict"`：原区间可行但所选顺序连 g=0 都无法保持，`conflict.steps` 闭合矛盾链中顺序间隔环节为 `kind: "order"`、`line: null`，另带 `position`（相邻对序号）、`bound`（间隔下界，此时为 0）与 `relation` 含义；
  - `status: "interval_conflict"`：原区间自身矛盾，`conflict` 为与 `/api/solve` 相同的闭合矛盾链（尚未加入间隔约束）；
  - `status: "error"`：`errors`（区间行错误与顺序文本错误合并，顺序错误以“事件顺序第N行”前缀标注；不足两个事件、事件重复出现、事件未在区间中出现均在此返回，含原始行号）。
- `POST /api/clock-align` — 请求体 `{"text": "区间文本（可留空）", "records": "来源,事件,本地分钟\n…"}`（首个来源为参考时钟，偏移固定 0；同一来源共用一个整数分钟偏移，事件真实分钟 = 本地分钟 + 偏移），记录等式与区间共同联立：
  - `status: "ok"`：`reference`（参考时钟来源名）、`sources`（每个来源 `reference` 是否参考时钟、`located` 是否与参考时钟连通、`offset_low/offset_high` 最紧偏移（分钟，未定位为 `null`，参考来源恒为 0）、`exact` 是否精确点、`record_count`）、`events`（每个事件 `located`、`minute_low/minute_high` 真实分钟最紧界、`exact`）、`records`（逐条核对：记录 `line/source/event/local`、`reference/located`、`implied_low/implied_high` 本地分钟加偏移推出的真实分钟范围、`event_low/event_high` 事件真实分钟范围）及计数 `source_count/located_count/record_count/interval_line_count/event_count`；
  - `status: "conflict"`：`conflict.steps` 闭合冲突链，每环含 `source`（`"interval"` 区间行 / `"clock"` 记录行）、`line` 对应文本的原始行号、`kind`/`kind_label`（上界/下界/记录等式）、`bound` 界值（记录环为本地分钟）、`relation` 含义（记录环节点显示为“时钟(来源)”）；
  - `status: "error"`：`errors`（区间行错误与记录行错误合并，记录错误以“时钟记录第N行”前缀标注）。
- `POST /api/tolerance` — 请求体 `{"text": "区间文本"}`，把每条 `[lo,hi]` 同时扩为 `[lo−k,hi+k]`（k 为非负整数分钟），求使全部约束可解的最小 k。**分钟字段一律为十进制字符串**（分钟可为任意大整数，如 `9007199254740993`，不截断、不转浮点），**计数与行号保持数值**：
  - `status: "ok"`：`k`（最小统一容差分钟数，字符串）、`original_feasible`（原文 k=0 是否已可行）、`timeline`（扩展后约束的一条可行时间线，每项 `event/minute`，`minute` 为字符串，最早事件为第 0 分钟；空约束集时为空数组）、`rows`（每行含 `line`（数值行号）`/a/b`、`low/high` 原区间、`expanded_low/expanded_high` 扩展区间、`low_shift/high_shift` 两端放宽量（均为 k）、`actual` 本时间线差值、`lower_slack/upper_slack` 距扩展两端富余——均为字符串，`fits_original/fits_expanded` 是否满足原/扩展区间——布尔）、`total_lines/event_count`（数值）与 `message`；k>0 时另带 `blocking_conflict`：其 `conflict.steps` 为 k−1 时的闭合冲突链（每环含 `line` 数值原始行号、`kind` 上界/下界、`weight`/`bound`/`original_bound`/`expanded_bound`/`slack` 等分钟字段——均为字符串——与 `relation`），`conflict` 另含 `weight_sum`（k−1 扩展界环权和，为负）、`original_weight_sum`（原界环权和 W）、`slack_tested`（k−1）、`required_k`（⌈−W/L⌉，恰为 k）——均为字符串——`cycle_length`（环长 L，数值）与 `closes_to`；k=0 时 `blocking_conflict` 为 `null`；
  - `status: "error"`：`errors`（逐行校验错误，含原始行号）。
